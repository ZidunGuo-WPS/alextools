# parallel-pack 压缩耗时（实测）

在同一块数据上对比 **`tar -czf`** 与 **`parallel-pack`** 的墙钟时间（`time` 输出的 **real**），说明分层并行打包带来的加速。

## 环境与数据

- **数据目录**：本地某一固定根目录下的图片树（约 **13** 个一级子文件夹：其中 **12** 个各约 **1000** 张图、**1** 个约 **253** 张；具体规模以磁盘为准）。下表不写出真实路径。
- **命令**：对上述根目录执行 `tar -czf` / `parallel-pack`（与当时终端一致）；每种配置 **单次** 测量（未做多次取中位数；若要更稳可每种跑多轮取中位数）。
- **基线**：`tar -czf`（整棵树打一个 `.tar.gz`），与 **`parallel-pack -d 0`** 同属 gzip 压缩，可比。

## 结果（墙钟 real）

| 方式 | real | 相对 `tar -czf` |
|------|------|-----------------|
| `tar -czf`（gzip 基线，整棵树） | 103.2 s | 1.00× |
| `parallel-pack -d 0` | 100.5 s | **1.03×** |
| `parallel-pack -d 1 -j 2` | 74.0 s | **1.39×** |
| `parallel-pack -d 1 -j 3` | 59.5 s | **1.73×** |
| `parallel-pack -d 1 -j 4` | 48.1 s | **2.15×** |
| `parallel-pack -d 1 -j 6` | 41.8 s | **2.47×** |
| `parallel-pack -d 1 -j 12` | 32.0 s | **3.22×** |

表中 **「相对 `tar -czf`」** 为 \(T_{\text{tar -czf}} / T_{\text{本行}}\)：大于 1 表示比基线更快；例如 **3.22×** 表示墙钟时间缩短到约 **31%**。

## 简要结论

- **`-d 0`** 与单次 `tar -czf` 接近（略快），符合「同一类 gzip 单流」的预期。
- **`-d 1`** 随 **`-j`** 增大，墙钟时间明显下降；在本数据上 **`-j 12`** 相对 **`tar -czf` 约 3.2×** 加速，体现「多子目录并行 gzip + 再合并」的收益。
- **user** 时间随 `-j` 仍约 1m50s 量级，说明总 CPU 工作量相近，缩短主要来自 **并行重叠**；具体曲线会因磁盘、CPU、目录结构而变。

复测时在**同一台机器、同一数据路径**下用 `time` 执行相同参数即可；勿将本表中的时间与别机直接对比。
